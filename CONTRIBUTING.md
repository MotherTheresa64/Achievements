# Contributing

This repository is a workflow lab. Contributions should stay small, focused, and easy to review.

## Development process

1. Start from an issue when practical.
2. Create a descriptive branch such as `docs/...`, `feat/...`, or `chore/...`.
3. Keep commits scoped to one purpose.
4. Open a pull request with a concise summary and verification notes.
5. Merge only after the change is understandable from the PR history.

## Commit style

Use short conventional-style messages where useful, for example:

- `docs: clarify repository purpose`
- `feat: add workflow status check`
- `chore: add issue templates`

## Transparency

This project exists to practice GitHub features. It should never imply outside contributors, reviews, stars, or production usage that did not actually occur.
